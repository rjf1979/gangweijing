# 岗位镜 Web 视觉改版落地方案

> 版本：v1.0  
> 日期：2026-08-07  
> 目标：将现有流程型 AI 简历分析工具改造成参考图所示的网格、粗描边、荧光色和硬阴影风格，同时保持表单效率、报告可读性和移动端可用性。

## 1. 改版原则

- 风格定位：工具型 Neo-brutalist，不直接复制海报布局。
- 业务优先：注册、上传、确认等高频操作保持简单，每页只保留一个主要行动。
- 信息可核实：报告中区分匹配证据、缺口、风险和待核实项，不把颜色或单一百分比当作结论依据。
- 渐进改造：只改前端展示层，不改变 AI、邮件、数据库和现有 URL 流程。
- 响应式优先：先保证 375px 手机宽度，再扩展至平板和桌面。

## 2. 视觉设计令牌

统一写入 `styles.css` 的 `:root`，组件内禁止使用未登记的页面级颜色。

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--color-bg` | `#F7F5EE` | 页面米白背景 |
| `--color-ink` | `#111111` | 正文、标题、描边 |
| `--color-surface` | `#FFFFFF` | 内容面板、输入区域 |
| `--color-lime` | `#C7FF3D` | 主按钮、完成、核心强调 |
| `--color-blue` | `#73C7FF` | 信息、上传、识别结果 |
| `--color-yellow` | `#FFD84D` | 待确认、部分匹配 |
| `--color-pink` | `#FF8FA3` | 风险、缺口、错误提醒 |
| `--color-green` | `#79E39A` | 成功、已验证、已完成 |
| `--color-muted` | `#4A4A4A` | 辅助文字 |
| `--border-strong` | `3px solid #111111` | 主面板和输入框 |
| `--shadow-hard-sm` | `4px 4px 0 #111111` | 按钮、标签 |
| `--shadow-hard-md` | `7px 7px 0 #111111` | 页面主面板 |
| `--radius-md` | `10px` | 面板和按钮圆角 |

网格背景使用 CSS 两层线性渐变，网格尺寸 24px，颜色使用 `#11111112`，不新增背景图片。

### 字体与排版

- 中文优先使用系统无衬线字体：`Inter, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 页面标题 28-40px，区块标题 20-24px，正文不低于 16px。
- 正文行高 1.5-1.7，桌面单行长度控制在 60-75 个字符。
- 数值和日期使用等宽数字，避免报告列表刷新时宽度跳动。

## 3. 页面改造清单

### 3.1 登录、注册、邮箱验证

- 顶部增加小标签：`01 / ACCOUNT`。
- 白色表单面板、黑色粗边框、硬阴影。
- 主按钮使用荧光绿，禁用状态降低透明度并保留文字说明。
- 错误显示在对应字段下方；验证成功显示绿色状态块。
- 保留全局加载层，页面切换时避免登录表单闪现。

### 3.2 `/facts` 简历事实确认

展示流程：`简历已解析 -> AI 提取事实 -> 用户确认 -> 岗位匹配`。

- 基本信息使用蓝色区块。
- 工作经历使用荧光绿区块。
- 技能和量化成果使用黄色区块。
- AI 无法确认的内容使用粉色区块，并提供编辑入口。
- 每个事实项同时显示文字标签和状态图标，不能只依赖颜色。

### 3.3 `/job` 岗位截图识别

- 上传区使用蓝色背景、粗边框和明确的拖拽/选择入口。
- 识别结果使用白色面板，字段按公司、岗位、地点、职责、要求分组。
- 用户确认提示使用黄色区块。
- 页面只设置一个主操作：`确认岗位并生成分析`。
- OCR/AI 失败时保留重试按钮和手动编辑入口。

### 3.4 `/report` 报告详情

报告主体按照以下顺序呈现：

1. 总体结论
2. 匹配证据
3. 明显缺口
4. 风险与待核实项
5. 简历优化建议
6. 下一步行动

颜色语义：

- 绿色：已找到简历证据并匹配。
- 黄色：部分匹配或信息不足。
- 粉色：缺口、风险或冲突。
- 蓝色：岗位信息、外部数据或待核实内容。
- 荧光绿：建议执行的下一步行动。

匹配度必须拆分为技能、经验、行业、地点、硬性条件和证据完整度等维度，并显示依据。文案中明确“分析结果不代表实际录用概率”。

### 3.5 `/reports` 报告列表

- 使用紧凑的白色列表项，不做大面积仪表盘卡片。
- 报告名沿用 `YYYY-MM-DD_公司简称_岗位名`。
- 状态标签：分析中（蓝）、待确认（黄）、已完成（绿）、发送失败（粉）、已发送（荧光绿）。
- 支持状态筛选和空状态操作入口。
- 长公司名和岗位名允许换行，不强制截断。

### 3.6 `/my-resume`

- 中央保持白色文档阅读区，保证简历正文清晰。
- 外围工具栏使用网格背景、标签和粗边框。
- 打印/保存 PDF 按钮保持标准工具按钮样式。
- 不使用彩色背景覆盖简历正文，也不把简历内容做成多层嵌套卡片。

## 4. 前端组件与文件落地

在现有原生 HTML/CSS/JS 结构中增加以下通用类，不引入新的 UI 框架：

- `.neo-panel`：白底、粗边框、硬阴影内容面板。
- `.neo-button`：统一主按钮、次按钮、危险按钮和禁用状态。
- `.neo-tag`：页面分类、报告状态和小型标签。
- `.neo-step`：流程步骤块及完成/当前/待处理状态。
- `.neo-section`：报告区块，支持不同语义颜色。
- `.neo-alert`：成功、错误、待确认和提示信息。
- `.neo-grid`：响应式信息网格。

建议修改范围：

- `styles.css`：设计令牌、网格背景、组件样式、响应式断点和 reduced-motion。
- `index.html`：补充语义 class、步骤容器、状态标签和无障碍属性。
- `app.js`：仅调整状态 class、加载状态和报告区块渲染，不改变 API 合约。

## 5. 实施顺序

### 阶段一：视觉基础

- 建立令牌和全局网格背景。
- 统一按钮、输入框、面板、标签、焦点环和加载状态。
- 统一桌面/移动端容器宽度与间距。

### 阶段二：核心页面

- 先改造 `/facts`、`/job`、`/report`。
- 验证动态 AI 内容、错误、空状态和长文本布局。

### 阶段三：外围页面

- 改造登录/注册/验证、`/reports`、`/my-resume`。
- 统一返回、邮件状态和报告状态展示。

### 阶段四：视觉与可用性验收

- 桌面：1440px、1024px。
- 移动端：375px、768px，含横屏。
- 键盘 Tab 顺序、可见焦点环、表单错误定位。
- `prefers-reduced-motion` 下关闭非必要动画。
- 检查 AI 失败、邮件未验证、无简历、无报告和网络超时状态。

## 6. 验收标准

- 所有页面颜色和阴影来自设计令牌。
- 每个页面只有一个主要 CTA。
- 任何状态都不只依赖颜色，必须有文字或图标。
- 移动端无横向滚动，触控目标不小于 44px。
- 正文和按钮文字达到 WCAG AA 对比度。
- 报告长文本、长岗位名和长公司名不会破坏布局。
- 注册、验证、简历上传、岗位识别、报告生成、报告列表和邮件状态流程保持可用。
- `node --check app.js` 和 `node --check server.js` 通过。

## 7. 明确不做的内容

- 不重写后端 API、AI 调用、Resend 邮件和 PostgreSQL 持久化。
- 不把分析分数包装成真实录用成功率。
- 不把所有页面改成复杂的海报式大卡片。
- 不提交 `.env`、数据库密码、服务器配置或用户简历数据。
